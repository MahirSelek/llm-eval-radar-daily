Key Takeaways

  • Treat agent memory evals as incomplete unless they score notes outside the dialogue or task scope that produced them; in-scope recall can hide systematic intent widening.
  • Budget and calibrate LLM judges as a scaling bottleneck: as suites grow, cost, score drift, and non-transferable judge prompts dominate measured progress more than model deltas.
  • Pin provider SDK floors in harnesses such as Inspect AI; dual shims improve short-term convenience but weaken run-to-run comparability across labs.
  • Keep informal proxies (Codenames-style skill games, literary benchmark essays) labeled as exploratory signal, not as substitutes for protocol-specified tasks with leakage and contamination controls.

The most consequential item is the 2026-11-08 Medium piece on agent-written memory notes. The reported finding is blunt: when agents author their own memory, those notes widened what the user had actually said in 93% of cases, and the study’s distinctive move is testing memory outside the scope in which it was formed. That design choice matters more than the headline percentage. Standard memory evaluations often score retrieval fidelity inside the same conversation, tool session, or task envelope that created the note. Under that regime, a widened paraphrase can still look helpful—more complete, more actionable—because the original ambiguity is still ambient. Out-of-scope transfer removes that ambient context. A note that quietly upgraded a preference into a requirement, or a tentative constraint into a hard rule, becomes a contamination source for later decisions. For evaluation teams, the implication is protocol-level: memory benches should report both in-scope recall and out-of-scope reuse, with explicit rubrics for intent preservation versus elaboration. Without the second axis, labs can optimize for notes that read well locally while degrading long-horizon agent reliability.

That memory result also reframes leakage and contamination language for agent stacks. Leakage is usually discussed as train-test overlap in static datasets. Here the leakage channel is self-authored state: the agent writes a compressed world model that later acts like privileged context. If graders only check whether the note mentions the right entities, they miss whether the note invents commitments. Practical remediation for researchers and infra teams is to log memory write events with provenance (source utterance spans), score widening with paired human or constrained judges, and gate memory promotion behind a scope tag that later tasks can refuse. Comparability across systems then depends on whether those provenance and scope fields are part of the harness contract, not an optional log line.

A second freshness-window thread, dated 2026-11-07, attacks a different reliability surface: LLM-as-judge economics and stability. The Medium article on Jev-based evals with Clef as the judge frames three problems that appear as soon as a suite grows, leading with cost—every case becoming a paid call to a large model. Even without overclaiming the product layer, the evaluation thesis is familiar and still under-operationalized: judge cost scales with suite size, judge variance scales with prompt sensitivity, and both interact with contamination if the judge model has seen similar rubrics or answers. Alternatives that shrink the judge—specialized scorers, cheaper models, structured evidence checks—only improve evaluation quality if they publish agreement studies against a fixed human or high-tier reference panel on the same items. Otherwise a cheaper judge is just a different bias with a lower invoice. For infra teams, the actionable requirement is versioned judge configs: model id, temperature, rubric hash, and aggregation rule recorded per run, plus a holdout disagreement set that is never used for prompt tuning.

Harness hygiene appears in the 2026-11-08 Inspect AI commit that raises provider SDK floors instead of shimming both versions. This is not a new benchmark, but it is a reproducibility control. Dual shims let pipelines keep running while SDKs diverge; they also create silent forks where two labs believe they ran the same Inspect task yet differ in client behavior, retries, tool schemas, or streaming edge cases. Raising floors forces an explicit compatibility cliff. Evaluation platforms should treat that cliff as a feature for scientific reporting: declare the minimum SDK versions in the paper or dashboard, refuse mixed fleets in a single leaderboard slice, and re-baseline after floor bumps. Without that, apparent model gains can be harness migrations.

Methodology Risks

Comparability risk is elevated on thin days because informal proxies and essayistic benchmarking talk can be mistaken for protocol advances. Codenames-style skill boards, product demos, and literary essays do not share fixed item banks, contamination audits, or harness locks; mixing them into the same ranking frame as Inspect-style tasks invents false precision. Any cross-system claim this week should require identical task definitions, identical judge or scorer versions, and declared SDK floors.

Judge drift and leakage remain coupled. Replacing or cheapening LLM judges without a frozen agreement panel invites silent score shifts that look like model improvement. Memory notes add a second leakage channel: self-authored state that smuggles broadened intent into later trials. If graders only check topical overlap, widened memories pass; if suites never leave formation scope, the failure mode never appears.

Reproducibility depends on refusing dual-path convenience. Provider SDK shims, unpinned judge prompts, and unscoped memory stores all create runs that cannot be re-baselined after a dependency bump. Prefer hard floors, rubric hashes, and provenance-tagged memory writes over post-hoc narrative reconciliation.
