Deep Analysis

Same-day evaluation coverage for 2026-11-24 is thin. Across the provided fresh set, there is no new public LLM benchmark release, no judge-calibration study, and no arena methodology update dated to the report day itself. Under the stated freshness policy, the correct editorial move is not to stretch weak OpenAlex or compiler items into fake eval headlines, but to mine the freshest technical artifacts that actually change how evaluation is run, logged, and compared. Two items from 2026-11-23 clear that bar: the inspect_ai 0.3.292 release and a Cursor forum report on long call content loss in harnessed agent workflows. Everything else either sits outside LLM evaluation methodology or is future-dated and should not be framed as today’s news.

The inspect_ai release is the primary signal. Version 0.3.292 (published 2026-11-23) introduces breaking changes that directly affect evaluation plumbing. exclude_samples() and zero_samples() now return None, and DispositionResult is no longer exported. Operators are told to read affected samples and scores from the log instead of result.applied or result.unchanged. In parallel, inspect log exclude and inspect log zero no longer accept --json and print a summary instead of per-sample lines. For research and infra teams, this is not a cosmetic CLI tweak. Many internal scoreboards, CI gates, and post-hoc contamination/ablation scripts assume structured per-sample disposition objects. If those scripts continue to expect the old return shape, a run can look complete while exclusion or zeroing was never correctly accounted for in downstream aggregation. That is a classic reproducibility failure mode: the model and task are unchanged, but the accounting surface moved.

Why this matters for evaluation quality now is straightforward. Sample exclusion and zeroing are used for leakage quarantine, broken item removal, sandbox failure handling, and post-hoc fairness corrections. When the API stops returning applied/unchanged dispositions and forces log-centric recovery, teams that do not update parsers will either (1) under-count filtered samples and inflate accuracy, (2) double-count or drop zeros, or (3) silently skip quarantine steps because the old object path is None. Any of those outcomes contaminates cross-run comparison. The release also changes sandbox provider lifecycle semantics: task_init, task_init_environment, and task_cleanup now run in the launch directory instead of the task directory, and non-Docker providers whose task_init_environment returns variables fail setup with a PrerequisiteError. That is a harness validity issue. Agent benchmarks that depend on relative paths, local tool manifests, or provider-injected environment variables can change success rates after an upgrade even if the model checkpoint is identical. Without an explicit harness changelog in the paper or dashboard, such deltas will be misread as capability movement.

The practical implication for researchers is to treat 0.3.292 as a hard version pin boundary. Re-run a small frozen control suite before and after upgrade, keep the same seed and sample IDs, and verify that exclude/zero counts and score aggregates match after migrating to log-based recovery. For infra teams, update any automation that scraped --json exclude/zero output, assert DispositionResult is no longer imported, and add schema tests that fail if per-sample disposition fields are missing from logs. Also inventory custom sandbox providers: if they are not Docker or a Docker subclass and they return environment variables from task_init_environment, setup will now fail. That failure is preferable to silent misconfiguration, but only if teams notice it before a leaderboard cut.

The second fresh item is a Cursor forum thread dated 2026-11-23 titled “Long call content can be lost,” describing Grok Bot planning sessions whose long call content can disappear while work is handed to T3 Code harnesses. On its face this is a product bug report, not a benchmark paper. For evaluation methodology it still matters because modern agent scoring increasingly depends on process evidence: tool calls, intermediate plans, recovered errors, and multi-step state. If long-call content is truncated or lost, judges and human auditors lose the transcript needed to score partial credit, detect reward hacking, or reproduce failure modes. Final-answer-only metrics can remain computable while the run becomes scientifically incomplete. That asymmetry is dangerous in harnessed coding agents, where the interesting failure often lives in the middle of the trajectory.

Compare the two signals. Inspect’s breaking changes are explicit and versioned: they announce that old result objects and CLI shapes are gone. The long-call loss report is observational and incomplete, but it points to a different class of validity threat: silent information attrition inside the eval surface. Explicit harness breaks are easier to catch with pin diffs and changelog gates. Silent trace loss is harder because scores may still post. Together they argue for a dual control strategy: (1) treat eval framework upgrades as methodology changes requiring re-baselining, and (2) treat full-transcript retention as a first-class acceptance criterion for agent runs, not an optional debug artifact.

Methodology Risks

Comparability risk is concentrated in inspect_ai 0.3.292’s disposition and CLI shape changes. Any pipeline still reading result.applied, result.unchanged, or --json exclude/zero output can mis-handle quarantined or zeroed samples after 2026-11-23, producing non-comparable aggregates across otherwise identical model runs. Sandbox lifecycle relocation to the launch directory further couples scores to provider and working-directory assumptions; without harness version pins, cross-day leaderboards conflate infra drift with capability change.

Leakage and judge-drift exposure is secondary today because no fresh judge benchmark landed, but incomplete long-call traces create a related audit failure. If intermediate planning or tool content is lost, LLM-as-a-judge and human review cannot reliably detect contaminated prompts, copied solution fragments, or process shortcuts. Process-level judges then either abstain or overfit to truncated context, which looks like judge instability when the root cause is missing evidence.

Reproducibility practice for this window: declare thin same-day research coverage explicitly, cite the 2026-11-23 harness and forum dates, refuse to elevate future-dated or off-domain OpenAlex items as LLM eval news, and require log-schema plus transcript-completeness checks before publishing score deltas.
